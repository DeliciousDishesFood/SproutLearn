# 审查：新前端 v1.1（接口对齐 / 功能缺失 / 不可用状态）

> 审查对象：`frontend-v3`，基线 `a77fa55`。  
> 审查方式：源码 + 用户三张真实截图 + board-ui dashboard 参考 + 上一轮 P13。  
> 结论用于派工，不直接改代码。

---

## 一、接口对齐

| 能力 | 契约现状 | 前端现状 | 结论 |
|---|---|---|---|
| 题库模板导入 | `POST /classes/{id}/questions/import/preview` + `commit` | 已接，但只认 `.json/.xlsx/.xls/.csv` | 可用；`.xls` 表头不标准会 42203 |
| AI 智能识别导入 | v1 无此路由 | 无 `aiPreview`，无 AI tab | **缺接口 + 缺前端**；v1.1 新增 1 条 `ai-preview` |
| `QuestionImportPreview` | 现有字段完整 | 缺 `mode/engine/model/degraded/warnings/source_name/source_chars/truncated` | 需追加可选字段，两个 contract 镜像同步 |
| 题库选择器 | 无图标要求 | `BaseSelect` 只有 `ChevronDown`，无题库语义图标 | 需加 `icon` prop + `Library` SVG |
| 组卷题目分页 | `page_size <= 50` | 固定 50，底部大按钮常驻 | 分页本身可用；可见性/文案需改 |
| 学生状态筛选 | 无 `GET /classes/{id}/attempts`；只有 `papers/{id}/attempts` | 工作台无此功能 | **不新增 endpoint**；前端用 papers + students + attempts 聚合 |
| 工作台待复核 | `TeacherWorkbench.pending_review` 是题目数 | 顶部统计卡 + 底部复核卡 | 顶部保留；底部模板删除 |
| 热力活动 | `ActivityDay {date,answers,active_students,xp?}` | 按 `answers` 着色，月份标签有 bug | 口径可用；月份/状态组件需修 |
| 数字动效 | 无契约要求 | `StatCard` 静态 | 纯前端能力，参照 aitlas countUp |

## 二、功能缺失

1. **AI 智能识别导入**：教师无法把 PDF/Word/PPT/TXT/Markdown 题库导入；
   旧模板只认四种格式，用户 `sql题库.xls` 直接失败。
2. **AI 预览**：即使后端识别成功，前端也没有地方展示题型/题干/答案/警告；
   无法在入库前确认。
3. **模板下载/格式提示**：导入失败只有「题库文件格式错误」，没有支持格式、
   没有 CSV 模板、没有“改用 AI”的出口。
4. **题库选择器语义图标**：题库筛选/目标题库/组卷题库都只有 chevron，
   看起来像原生 select；缺少“这是一个题库”的视觉锚点。
5. **加载更多可见性**：组卷题目列表的 footer 在滚动容器外，128 题时
   一直显示大按钮 + “已加载 50 / 共 128 题”，挤占列表空间。
6. **设置页开关居中**：`.switch i::after` 依赖 `margin:2px`，在部分缩放下
   滑块偏上；缺少绝对居中。
7. **数字动效**：教师/学生工作台、热力统计数字都是静态，没有“变化”感。
8. **热力月份**：只按列首日判断月份，9 月从第 3 列才出现；`span 2` 还会
   让 8/9 月标签重叠或间距不均。
9. **热力状态组件**：悬浮只有一行文本，没有色点/等级/次数/XP 的状态 chip。
10. **工作台学生状态**：没有“考试 + 状态”筛选，无法回答“这场考试谁没开始/
    谁待复核”。
11. **组卷原生 checkbox**：题目选择用浏览器原生 checkbox，与整体视觉不一致。

## 三、不可用 / 易误判状态

| 状态 | 触发 | 现在会发生什么 | 应该怎样 |
|---|---|---|---|
| 模板格式错误 | `.xls` 表头不标准 | 红色「题库文件格式错误，请按模板修正后重试」，没有下一步 | 说明支持格式 + 下载模板 + 切 AI |
| AI 未配置 | 后端无 LLM key / provider 全挂 | 前端没有入口，无法感知 | 明确 50301 文案 + 保留模板导入 |
| AI 识别 0 题 | 扫描 PDF / 图片 / 空文本 | 无预览，确认按钮仍可能可点 | 42203/valid_count=0 时禁用确认 |
| 加载更多 | 列表未到底 | 大按钮一直可见，误以为还有大量内容 | 只有滚到底部才出现小字 |
| 热力月份 | 9/1 在列中间 | 9 月标签推迟、8/9 月拥挤 | 按列内任意一天分段，标签段内居中 |
| 工作台无待复核 | `pending_review=0` | 底部出现「暂无待复核题目」空模板 | 删除该卡，不占版面 |
| 学生状态无考试 | 班级没有考试 | 无此区域 | 空态说明“发布考试后出现” |
| 切班/换考试 | 异步请求返回顺序颠倒 | 旧班/旧考试数据覆盖新选择 | 请求序号/AbortController 守卫 |
| 200 信封错误 | code!=0 但 HTTP 200 | 上一轮已修，共用 `handleApiError` | 不回退 |
| badge 拉伸 | 表格 grid 子项 | 上一轮已修 `fit-content + justify-self:end` | 不回退 |

## 六、审查结论

新前端 v1 的视觉与主链路已经可用，但这一轮用户点名的问题集中在
**“入口不像产品”“状态看不见”“数据到了但没反馈”**：

- 导入入口仍是浏览器原生控件，且不支持真实题库格式；
- 组卷列表的分页状态一直外露；
- 热力的月份/状态反馈不完整；
- 工作台底部被一个空模板占据，缺少真正的学生状态视图。

派工按 `docs/派工-新前端v1.1-UI打磨.md` 执行；AI 后端按
`docs/派工-题库AI导入-后端.md` 执行。两边都不新增依赖、不改 v1 现有路由、
不 commit；由主窗口统一验收与提交。
