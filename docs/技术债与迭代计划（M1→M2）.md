# 技术债与迭代计划（M1 → M2）

> 制定人：副指挥官　日期：2026-11-08
> 原则：**M1 主线只做「联调 + L2 验收 + 修 P0」**；非阻断的技术债统一进队列，等 M1 基线稳定后开 `refactor` 批次一次性处理，避免边开发边升级把回归面放大。

## 1. 当前批次边界（M1 收尾）

做：真实栈联调、seed 幂等回归、API-18 类型补齐、L2 语义审阅、P0/P1 修复。
不做：依赖升级、UI 组件库替换、M2 功能、性能优化、浏览器矩阵扩展。

## 3. refactor 批次（M1 稳定后启动）

**触发条件**：M1 通过 L2、演示脚本连跑两次成功、无 P0 遗留。

**批次内容（一次做完，一次回归）**：
1. 后端：`pytest-asyncio` 配置补齐 + `starlette/httpx` 依赖升级；升级后 `pytest` 全量回归。
2. 前端：UI 组件库评估接入（保留 `tokens.css` 与现有视觉基线，禁止默认皮肤直出）；接入后 `npm run build` + 截图比对。
3. 两者同批合并，跑一次「pytest + build + 20 接口契约比对 + AC-31 主链路」全量回归，回归清单进 `dev-docs\reports\`。

**禁止**：refactor 批次里夹带新功能；功能改动必须另开分支。
