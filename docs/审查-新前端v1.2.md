# 审查：新前端 v1.2（数据一致性 / 信息减负 / 热力对齐 / 打字机）

日期：2026-11-16
基线：`8de685f feat(v3.1): 新前端 v1.1 落地 UI 打磨与题库 AI 导入`
范围：`frontend-v3/` 主线、`backend/` 只读诊断、旧 `frontend/` 只读对照。

## 一、结论

这轮不是“再补几个样式”，而是先解决三个会让演示翻车的基础问题：**数据源漂移、会话假登录、热力图坐标错误**。用户看到的“数据有时旧、有时新”，当前证据指向同一个 8000 端口上跑过不同后端（契约 SQLite / 生产 MySQL），不是新旧前端本身在改数据。前端又把问题放大了：本地缓存了 user，路由只在 `user` 为空时才拉 `/auth/me`，所以换后端后仍显示上一个账号；`currentClassId` 也持久化，旧班级 ID 可能在新库不存在。

v1.1 已有不少修复被旧截图“盖住”了：原生 file input 已隐藏、AI tab 已存在、SVG 选择器、加载更多小字、switch 2px、countUp、学生状态筛选都在源码里。**AI 导入“消失”的真实原因是 `openImport()` 每次强制 `importMode = 'template'`**，用户打开弹窗永远先看到模板导入。这个必须改。

## 二、证据与根因

### 1. 数据源：8000 上当前是契约 SQLite，不是旧 MySQL

- 8000 监听进程 PID 42012，命令行 `C:\Users\OMEN\venvs\sproutlearn-backend\Scripts\python.exe serve_contract.py`；8032 进程已不在监听，8010 空闲。
- 直接登录 8000：教师 `teacher@sprout.local`，姓名 `张老师`；班级 `2026级计算机1班`，3 名学生。`contract.db` 的 teacher 表也只有 `张老师`，没有旧截图的 `吴开风`，也没有 v1.1 截图的 `林清和` / `高二(2)班`。
- 旧 `frontend/vite.config.ts` 与新 `frontend-v3/vite.config.ts` 都代理 `http://127.0.0.1:8000`。所以“新旧前端数据不同”不是前端请求路径不同，而是**8000 上后端换过**。
- 契约服 `SECRET_KEY` 是 `contract-demo-secret-key-please-do-not-use-in-prod`；生产根 `.env` 是另一套。两套 token 互不认，切后端必然 401。
- 本机 MySQL80 服务在跑，但 `sproutlearn` / `root` 多组凭据均 1045；Redis 6379 未监听；Docker Desktop 进程在但 `com.docker.service` 停止、`dockerDesktopLinuxEngine` 管道不存在，当前用户无法启动服务。**旧 MySQL 数据今晚不可达，不能假装已恢复。**

### 2. 会话：前端在“演”一个已经失效的账号

- `auth.ts` 从 localStorage 读 token + user；`isLoggedIn` 只看 token。
- `router/index.ts` 的守卫只在 `!auth.user` 时才 `fetchMe()`。只要本地有旧 user，**永远不会校验 token 是否属于当前后端**。
- 换后端后：侧栏仍显示旧姓名/旧班级 → 点任意页面 401/404 → 点退出又发一个没有 Authorization 的 `POST /auth/logout` → 401。截图 `referrer /teacher/classes`、无 Authorization 就是这么来的。
- `authApi.logout()` 只设 `skipGlobalError`，没设 `skipAuthRedirect`；`auth.logout()` 无论有没有 token 都发请求；`main.ts` 的 session-expired 只清 auth，不清 `currentClassId`。
- `frontend-v3/src/stores/ui.ts` 持久化 `sprout.v3.currentClassId`；只有 `DashboardView` 用 `classes.some()` 校验，其他页面直接拿这个 ID 去请求，旧库切新库时会 404 或空数据。

### 3. 文案：接口不一定没有，前端本地兜底把“没有”伪装成“有”

- `GET /quotes/random` 在 8000 实测 200，返回 `{"text":"路漫漫其修远兮，吾将上下而求索。","from":"屈原","source":"local"}`。所以“文案接口没有”至少当前契约服不成立。
- 前端仍有**本地硬编码兜底**：`DashboardView.vue` 的 `'把复杂讲简单，把简单讲深刻。' / '青芽教学手记'`；`student/HomeView.vue` 同；`LoginView.vue` 本地 `defaultQuote`；`RegisterTeacherView.vue`、`JoinClassView.vue` 的故事金句。接口失败时仍显示这些句子，用户会误以为接口正常。
- 结论：删除前端本地句子，接口失败就留空/隐藏；后端 `source=local` 的返回可以显示，因为那是接口真实结果。

### 4. 题库：第一次创建确实有两个入口

- `BanksView.vue` 页头 `BaseButton` “新建题库”；空态 `EmptyState action-label="新建题库" @action="openCreate"`。两处同时出现。
- `ClassListView.vue`、`PapersView.vue`、`QuestionsView.vue` 也有“页头主按钮 + 空态 action”的同类结构，需要一起收口。
- 原则：页头已有主操作时，空态只做信息展示；只有“页头没有入口、且空态是唯一下一步”时才保留空态按钮（如班级详情“查看邀请码”、批改枢纽“去组卷”）。

### 5. 热力图：不是标签没调好，是坐标系错了

`HeatDots.vue` 现状：
- `.heat-grid` 写死 `grid-template-columns: repeat(12, 13px)`，即使 `weeks` 传 52 也还是 12 列；`cells` 会按 12 列折成 52 行。
- `cells` 从“今天往前 N 天”生成，第一格不保证是周日；但 grid 的 7 行从上到下是周日→周六。当前窗口 2026-08-24 是周一，第一格周一被放在“周日”行，**整张图星期错位一天**。
- 月份标签是独立 `.heat-months` grid，每个 `span` 用 `gridColumn: start+1 / end+2` + `text-align:center`。12 周只有 4 个月，8 月 1 列、9 月 4 列、10 月 4 列、11 月 3 列，标签按“段中心”排，间隔天然 60/80/70px，用户看到的就是“没和月份列对齐、间隔不一致”。
- 12 周窗口下，8 月只占 1 列，LeetCode 式“月份落在月首列”必然和 9 月标签挤在一起；**12 周这个窗口本身不适合做 4 个月标签的 LeetCode 排版**。

结论：改成 **52 周、单块 SVG / 单一坐标系**，月份标签按“月首列”左对齐，不再用独立 grid 居中。后端 `weeks` 最大 52，`workbenchApi.classActivity/studentActivity` 已支持，Dashboard 目前只请求 12。

### 6. AI 导入：入口在，只是每次被强制回模板

- `importMode` 初始 `'template'`；`openImport()` 里又写 `importMode.value = 'template'`。所以用户每次打开都只看到模板导入，AI 智能识别 tab 被重置掉。
- 原生 input 在 v1.1 已隐藏（`upload-input` + `tabindex=-1 aria-hidden=true`），上传区是 `upload-zone`；用户截图里的“选择文件”是 v1.1 之前的形态。
- `AI_ACCEPT` 已含 `.pdf/.docx/.pptx/.xlsx/.xls/.csv/.json/.txt/.md`；`.xls` 在 AI 模式可解析，模板模式仍只认 `.xlsx/.xls/.csv/.json`，所以 `sql题库.xls` 在模板模式报 42203 是预期行为。
- 结论：默认进 AI tab，模板保留为第二 tab；用真实 `.xls` 做一次 AI 预览，不再让用户以为 AI 没了。

### 7. 打字机：aitlas 组件是纯前端，可直接复用骨架

`E:\ai-dev-projects\aitlas\frontend\src\components\TypewriterText.vue`：逐字 `setTimeout`、光标 `|` 闪烁、`prefers-reduced-motion` 直显、卸载清 timer；它自己拉 hitokoto。SproutLearn 只复用**组件骨架和样式**，文本由 `workbenchApi.quote()` 传入，不引入 hitokoto、不新增依赖、不新增字体/网络资源。

## 四、v1.2 决策

1. **数据源冻结**：录制前 8000 只跑契约 SQLite；不再启动 MySQL 后端抢 8000。旧 MySQL 数据恢复另立任务，需 Docker/凭据，不在今晚硬做。
2. **前端不伪装**：会话启动必须校验一次 `/auth/me`；班级 ID 必须对当前 `/classes` 校验；quote 失败不显示本地句子。
3. **文案减负**：删静态页头副标题、EmptyState 说明、StatCard hint、解释型 card meta、故事金句、工作台页脚；保留校验、危险确认、错误、计数/截止时间、空态下一步。
4. **题库空态去重**：页头有主按钮时，空态不再给同义按钮。
5. **热力重做**：52 周、单块 SVG、周日对齐、月份按列首左对齐；375 允许图内横向滚动，不允许页面横向溢出。
6. **打字机**：工作台标题下，替代静态 lede；删除底部金句条；不循环、不拉 hitokoto、reduced-motion 直显。
7. **工作台复核模板**：删除“待复核题目”统计卡与页头“去批改”快捷入口，保留侧栏“批改”；第四卡改“班级人数”。
8. **AI 导入默认**：打开即 AI 智能识别；模板作为降级 tab；真实 `.xls` 预览验收。

## 五、风险与未决

- 旧 MySQL 数据（吴开风那套）今天不可达；如果演示必须用旧数据，需要用户提供 MySQL 密码或允许启动 Docker Desktop 服务。当前 8000 的 `张老师/2026级计算机1班/3 学生` 是唯一可用数据。
- 52 周热力在当前 84 天种子上会左半空；这是真实数据形态，不是组件 bug。演示若嫌空，可让后端补 52 周种子或接受“过去一年”留白。
- 用户截图中的 `sql题库 (0)`、`未分类题库 (128 题)` 属于另一套数据；v1.2 不猜测、不重置 `contract.db`。
- 旧 `frontend/` 仍有大量未提交改动，**本轮不碰、不提交**；v1.2 提交只收 `frontend-v3` + v1.2 后端文件 + v1.2 docs。
