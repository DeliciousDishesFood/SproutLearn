# 青芽 SproutLearn · M2 学生邮箱账号体系升级需求（草案）

> 状态：**规划草案**，不进 M1 范围；M1 学生登录与账号逻辑维持现状（见决策日志 D-005）。
> 排期：核心教学闭环（题库 / 组卷 / 判分 / 讲评）完成之后启动，标记为高优先级架构优化。
> 关联：决策日志 D-006；契约 API-02（M1 口径，M2 需开变更单）。

## 1. 问题

M1 学生身份 = `(class_id, student_no)`，本质是「班级域唯一」：
- 同一学生在不同班级是两套账号，经验值、学习记录不互通；
- 不同学校学号重复无法全局识别；
- 学生换班/升班后历史数据割裂。

## 2. 目标模型（M2）

| 维度 | M1（现状） | M2（目标） |
|---|---|---|
| 全局唯一标识 | 无（学号仅班内唯一） | **邮箱**（`student_account.email`，全局唯一） |
| 登录方式 | `class_code + student_no + password` | `email + password` → 进入后选班级 |
| 学号 | 身份的一部分 | 退化为班内业务字段，`(class_id, student_no)` 仍唯一 |
| 多班级 | 不支持 | 一个邮箱可加入多个班级，班内 xp/等级/记录独立 |
| 注册 | 教师建号 / 邀请加入 | 邮箱验证码注册 → 设密码 → 填基本信息 → 邀请码加入班级 |
| 教师账号 | 邮箱/手机号（`account`） | 不变 |

**数据模型草案**（M2 立项时定稿，需走契约变更单）：

```
student_account(id, email UNIQUE, password_hash, nickname, status, created_at, updated_at)
student_enrollment(id, account_id, class_id, student_no, xp_total, level, status,
                   UNIQUE(class_id, student_no), UNIQUE(account_id, class_id),
                   FK account_id → student_account.id, FK class_id → class.id)
```

`student` 表在 M2 迁移后由 `student_account + student_enrollment` 替代；M1 期间不改。

## 3. 注册与登录流程

**注册**：输入邮箱 → 发 6 位验证码（有效期 5 分钟、同邮箱 60s 限流、错误 5 次锁定 10 分钟）→ 校验通过设密码 → 填昵称/学号 → 输入班级邀请码加入（邀请码仍由教师生成、可重置）。

**登录**：邮箱 + 密码 → 返回已加入班级列表 → 选择班级进入课堂；无班级时引导「输入邀请码加入」。

**错误码**（M2 新增，编号在 M2 契约里分配）：验证码错误/过期、邮箱已注册、发送过频、邮箱未注册等。

## 4. 邮件验证码配置

- 服务：QQ 邮箱 SMTP（`smtp.qq.com:465`，SSL），后续可平滑替换企业邮箱；
- 凭据：`EMAIL_SMTP_USER`、`EMAIL_SMTP_PASSWORD` 只存本机 `.env`，`.env.example` 只留字段名，**任何文档与仓库不得出现明文**；
- 发送失败策略：失败即提示重试，不允许静默降级为"无验证码注册"；
- 反滥用：同邮箱 60s、同 IP 每小时上限、验证码哈希存储不落明文。

## 5. 迁移（M1 → M2）

- M1 学生无邮箱，迁移必须提供「教师批量补邮箱」入口或 CSV 导入，禁止用假邮箱（`学号@class.local`）冒充真实账号；
- 迁移脚本需可重复执行（幂等），并在测试库先跑两遍；
- 迁移前备份，失败可回滚到 M1 结构；
- 迁移期兼容：M1 登录接口保留一个过渡版本（仅迁移窗口内可用），到期下线。

## 6. 影响面

| 模块 | 影响 |
|---|---|
| 契约 API-02/05/11 | 学生登录、加入班级、学生信息响应均需新版本 |
| 前端 | 登录页双输入 → 邮箱登录；新增注册页、验证码倒计时、班级选择页 |
| QQ 绑定 | 绑定主体由 student 行改为 `student_account` + 班级上下文，需重定语义 |
| 成长体系 | xp/等级挂到 `student_enrollment`，跨班不合并 |
| 验收 | 新增注册、验证码、多班级、迁移四组用例 |

## 7. 明确不做（M2 阶段）

- 不做学生自主换班/退班审批流（先由教师移除）；
- 不做第三方登录（微信/QQ OAuth）；
- 不做跨校联盟/全局学号体系。
