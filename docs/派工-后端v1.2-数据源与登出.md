## 三、任务清单

### D1 登出幂等：无 token / 坏 token 也返回 200

涉及：`backend/app/deps.py`、`backend/app/routers/auth.py`、`backend/tests/test_m25.py` 或新增 `backend/tests/test_auth_logout.py`

1. 在 `deps.py` 新增 `get_optional_token_claims`：
   - 无 `Authorization` / 非 Bearer / 空 token → 返回 `None`，不抛 401。
   - JWT 签名错/过期/缺 jti/sub → 返回 `None`，不抛 401。
   - 合法 token → 返回 payload（只验签，不要求 Redis 会话）。
2. `auth.py` 的 `logout` 改用可选 claims：
   - `payload` 为 None：直接 `success(None)`，HTTP 200 / code 0。
   - payload 有 jti：照旧 `auth_service.logout_claims(payload)`，写黑名单/删会话。
   - 重复登出仍 200。
3. 不改 `get_current_user` 的严格 401 行为；`/auth/me` 仍必须 401。
4. 测试：
   - 无 Authorization → 200/code 0。
   - `Authorization: Bearer bad.token` → 200/code 0。
   - 合法 token → 200，且后续 `/auth/me` 401/40102（会话已删）。
   - 连续两次合法 logout → 两次 200。

验收 curl（当前 8000 契约服）：

```powershell
curl.exe -i -X POST http://127.0.0.1:8000/api/v1/auth/logout
```

必须 `HTTP/1.1 200`，body `code=0`；不得 401。

### D2 健康检查：按实际业务库口径，不再误报 503

涉及：`backend/app/routers/health.py`、`backend/tests/test_m25.py` 或新增 `backend/tests/test_health.py`

1. `checks` 增加/改为：
   - `database`: `ok|error`（用 `engine.connect()` 的 `SELECT 1`，不要再叫 mysql）
   - `db_backend`: `engine.dialect.name`（`sqlite` / `mysql`）
   - `db_name`: `engine.url.database`（只给库名/SQLite 文件名，不给密码/host 凭据）
   - `redis_mode`: `fake` / `real`（用现有配置/客户端判断，不要猜）
   - `redis`: 保留 ok/error
   - `qdrant`: 保留
2. `required_ok` 只看**当前实际业务库**：数据库 ok 即通过；`redis` 只在 real 模式为必需；`qdrant` 仍按 `vector_index_enabled`。
3. `data` 增加运行 fingerprints：
   - `app_env`
   - `db_backend`
   - `db_name`
   - `seed_fingerprint`：对 teacher/class/student 的 count + 名称做 SHA256 前 8 位（只读查询；不要输出全名，避免隐私；可只 hash）
   - `jwt_secret_fingerprint`：`sha256(SECRET_KEY)[:8]`，绝不输出 secret
   - `started_at`（模块级时间即可）
   - `version`
4. 契约服 `/health` 必须 200；MySQL 真不可用才 503。
5. 不新增 `/meta` endpoint；前端不展示这些字段，只供主窗口/运维判断“当前是哪套库”。

验收：

```powershell
curl.exe -s http://127.0.0.1:8000/api/v1/health
```

契约服应 `HTTP 200`、`code=0`、`data.db_backend="sqlite"`；`jwt_secret_fingerprint` 有值且不等于 secret 明文。
