### 五、风险

1. **鉴权 DB 查询**：每次请求多一次 teacher/student 查询；是会话撤销最终依据，但会增加延迟；Redis 只做优化。
2. **旧 token 一次性失效**：部署后没有 `auth_version` 的旧 JWT 全部 40102，用户必须重新登录；这是安全预期，需在发布说明写明。
3. **归档只读范围**：已覆盖主要写路径，但若后续新增写路由未调用 `require_active_class`，可能绕过；需 review 新路由。
4. **临时密码交付**：只通过响应返回一次，响应/浏览器历史可能留存；不在日志/audit/数据库明文保存，前端必须避免缓存并提示用户立即改密。
5. **Redis 限流 fail-open**：Redis 故障时改密/重置限流放行，不是强一致安全边界；审计仍记录结果。
6. **归档恢复**：归档会递增学生 auth_version，恢复后旧登录会话不会复活；学生需重新登录，可能造成演示现场短暂中断。
7. **迁移差异**：MySQL 的 `BIGINT UNSIGNED`/索引与 SQLite 不完全等价；MySQL 未实跑，需在目标库执行 `alembic upgrade head` 后复核。
8. **审计范围**：`target_id` 不设外键，跨角色目标由应用保证；只记录最小字段，不能替代审计中心。
9. **教师归档自身班级**：教师 token 不递增版本，归档后仍可读取/恢复；写操作由 active guard 拦截，需确认产品接受教师可继续查看归档。
