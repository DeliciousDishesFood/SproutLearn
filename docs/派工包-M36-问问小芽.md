## 1. 冻结契约（前后端的唯一真源）

### 1.1 接口

```
POST /api/v1/attempts/{attempt_id}/ask
鉴权：学生 token（沿用现有学生鉴权依赖）
Content-Type: application/json
```

### 1.2 请求体

```json
{
  "question_id": 123,
  "selected_text": "学生选中的题干/选项原文，1-500 字",
  "message": "学生自己的问题，1-500 字（前端预填「关于我选中的“…”」）",
  "history": [
    {"role": "user", "content": "<=1000 字"},
    {"role": "assistant", "content": "<=1000 字"}
  ]
}
```

- `history` 最多 **6 条**（超出由后端截断为最近 6 条，**不报错**）。
- `role` 只允许 `user` / `assistant`。
- 以下情况 400：`selected_text` 空或 >500 字、`message` 空或 >500 字、`question_id` 缺失。

### 1.3 响应体（200）

传输层沿用项目统一信封，契约体放在 `data` 内（前端 `client.ts` 拦截器已对 `code === 0` 自动解包为 `data`，业务层拿到的就是下面的契约体，**前端不要手动再解一层**）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "answer": "纯文本，无 Markdown/LaTeX 残留",
    "sources": [{"doc_id": 12, "doc_name": "第三章 神经网络基础.pdf"}]
  },
  "request_id": "…",
  "timestamp": "2026-11-15 00:12:00"
}
```

- `sources` 只允许 `doc_id` 与 `doc_name` 两个字段，**不得**回传切片正文、路径、分数；无命中时为 `[]`。
- `answer` 为纯文本：后端负责清理 Markdown/LaTeX（可复用 `format_for_qq`），前端按纯文本渲染，不再二次 markdown 解析。

### 1.4 业务规则

| 规则 | 要求 |
|---|---|
| 归属 | `attempt` 存在且 `student_id = 当前学生` |
| 状态 | `attempt.status = doing` |
| 模式 | `paper.kind = practice` 才开放；`homework` / `exam` 一律拦截，文案「当前不是练习模式，小芽暂不开放」 |
| 题目归属 | `question_id` 必须属于该 paper |
| 答案隔离 | 只读题干/选项/知识点；**严禁**读取或拼进 prompt 任何正确答案、正确答案字段、解析内容 |
| 检索 | 复用 `retrieve_chunks(db, class_id=..., question=...)` |
| 生成 | 复用 `_race_chat` / `build_router` 多 provider 并行竞速，整体约 8 秒；系统提示苏格拉底式：先引导、不直接给最终答案、选择题不直接说选项、不编造学校制度 |
| 限流 | 同一学生 **3 秒 1 次** + **每天 40 次**；Redis 故障时**放行** |

### 1.5 错误码表（后端已落地，前端按 `code` 分支，不依赖文案）

| HTTP | 业务 code | 触发条件 | 前端行为 |
|---|---|---|---|
| 200 | 0 | 成功 | 追加 assistant 消息 + sources chip |
| 400 | 40001 | `selected_text` / `message` 为空或空白 | 就地提示，不重试 |
| 403 | 40301 | 非练习模式（`exam` / `homework`） | 关闭面板并隐藏入口，提示「当前不是练习模式，小芽暂不开放」 |
| 403 | 40302 | attempt 非本人 / 跨班 | 提示无权访问，不再重试 |
| 404 | 40401 | attempt 不存在 / 题目不属于该试卷 | 提示「题目已失效，请刷新」 |
| 409 | 40910 | attempt 状态非 `doing` | 关闭面板，提示本次作答已结束 |
| 429 | 42901 | 3 秒频控命中 / 今日超 40 次 | 提示稍后再试，不自动重试 |
| 503 | 50301 | LLM 全 provider 失败或超时 | 保留用户输入，出现「重试」按钮 |

> 错误响应同样走统一信封，前端 `ApiError.code` 即为上表业务 code。

### 1.6 字段映射（后端 → 前端类型）

| 后端 | 前端类型字段 | 类型 |
|---|---|---|
| `question_id` | `AttemptAskPayload.questionId` | `number` |
| `selected_text` | `AttemptAskPayload.selectedText` | `string` |
| `message` | `AttemptAskPayload.message` | `string` |
| `history[].role` | `AttemptAskPayload.history[].role` | `'user' \| 'assistant'` |
| `history[].content` | `AttemptAskPayload.history[].content` | `string` |
| `answer` | `AttemptAskResponse.answer` | `string` |
| `sources[].doc_id` | `AttemptAskResponse.sources[].docId` | `number` |
| `sources[].doc_name` | `AttemptAskResponse.sources[].docName` | `string` |
| `paper.kind`（resume 返回） | `AttemptPaper.kind?` | `'practice' \| 'homework' \| 'exam'` |

请求体按 **snake_case 原样上送**（前端 `AskSproutPayload` 直接用 `question_id` / `selected_text` 等字段名，不做驼峰转换）；响应由 `client.ts` 拦截器解包 `data`，业务层只拿契约体，**后端不再额外包一层**。`paper.kind` 由 `attempts.ts` 的 `resume()` 映射整包透传（`paper: { ...data.paper }`），不做字段裁剪——否则新增字段会被前端悄悄丢掉。
