## 1. 项目概述

青芽 SproutLearn 是面向班级教学的 AI 助学 Web 应用。项目不把大模型作为孤立聊天入口，而是将教师资料、题库、试卷、学生作答、AI 反馈、教师复核、学情和 QQ 班级服务组织成闭环：

> 教学资料 → 题库/组卷 → 学生作答 → 判分/讲评 → 教师复核 → 学情与通知

### 1.1 痛点

1. 教师已有资料格式不一，整理题库、统计提交和解释错题存在重复劳动。
2. 通用大模型容易脱离本班资料，学生难以判断答案依据。
3. 自动判分与生成式 AI 都可能失败，教学系统需要可识别、可降级的状态，而非假装成功。
4. 学生不一定持续打开教学网站，需要在其常用的 QQ 入口提供受权限控制的班级服务。

### 1.2 定位与目标

- 对教师：降低题库整理、作业统计和初步反馈成本，保留终审权。
- 对学生：提供有出处的问答、清晰作答反馈和持续成长记录。
- 对评审：可运行、可解释、可复现，明确区分真实实测、离线验证和未验收项。

## 2. 需求分析

### 2.1 角色与核心任务

| 角色 | 核心任务 | 权限边界 |
|---|---|---|
| 教师 | 建班、资料与题库管理、组卷发布、复核、学情、QQ 配置 | 仅管理本人班级；不能读取其他教师资源 |
| 学生 | 入班、作答、看成绩与讲评、提问、成长记录、QQ 绑定 | 仅访问所在班级和本人数据 |
| QQ 机器人 | 帮助、作业/成绩查询、AI 问答、作业通知 | 普通 @ 被动回复与主动群消息分权处理 |

### 2.2 功能需求

- 多格式题库文本抽取、AI 结构化、预览校验后入库。
- 班级资料上传、切片、状态管理与带来源检索问答。
- 固定/随机/整库组卷、发布、草稿恢复、提交、判分和复核。
- 官方解析、AI 讲评和模板降级分区展示。
- 经验、等级、连击、热力图与教师工作台。
- 密码修改、教师一次性重置、强制改密、会话撤销、学生停用和班级归档。
- QQ 群绑定、查询、AI 问答、主动通知状态记录和教师显式重试接口。

### 2.3 非功能需求

- 班级级数据隔离、密码哈希、环境变量托管密钥、敏感信息不入日志。
- 关键写操作具备权限和归档状态校验；AI 与第三方服务失败不能破坏核心教学数据。
- 支持桌面与手机网页，主要文本满足对比度检查，键盘焦点可见。
- Docker Compose 一键启动，数据库使用 Alembic 版本化迁移。

## 3. 系统架构

### 3.1 技术栈

| 层级 | 技术 | 职责 |
|---|---|---|
| 前端 | Vue 3、TypeScript、Vite、Pinia | 教师/学生 Web、状态管理、响应式交互 |
| API | FastAPI、SQLAlchemy | 鉴权、业务编排、AI 服务适配、统一错误码 |
| 数据 | MySQL | 账号、班级、题库、作答、通知、知识切片等业务数据 |
| 缓存 | Redis | 会话、限流、预览 token、短期状态 |
| 扩展组件 | Qdrant | 向量检索扩展与健康探针；当前问答未宣称使用向量召回 |
| AI | ModelRouter、Jev 判分适配器 | 多模型路由、熔断降级、语义判分与讲评 |
| 外部入口 | QQ 官方机器人 + 独立 worker | 群绑定、被动查询/问答、主动通知 |

### 3.2 前后端与契约

唯一前端主线为 `frontend-v3/`，旧 `frontend/` 冻结。后端接口前缀为 `/api/v1`，前端类型定义与 `docs/frontend-v3-contract/contract-types.ts` 镜像校验，减少前后端字段漂移。

### 3.3 关键数据流

1. 教师请求携带身份令牌，后端验证角色、班级归属、账号状态和 `auth_version`。
2. AI 导入只把待确认结果写入预览 token，教师确认后才形成正式题目。
3. 作答提交后保存答案和判分依据，异常结果进入教师复核，不以模型结果覆盖人工决定。
4. 发布试卷后先保证业务和站内通知持久化，再尝试 QQ 主动群通知；QQ 失败记录结构化原因。
5. QQ 查询复用班级/学生权限和知识检索；被动回复与主动发送分别处理。

## 4. AI 技术方案

### 4.1 多格式题库导入

支持带文字层的 PDF、DOCX、PPTX、XLSX、XLS、CSV、JSON、TXT、Markdown。管线为：

> 文件文本抽取 → 分段与长度控制 → LLM JSON 结构化 → 题型/选项/答案规则校验 → 错误定位与教师预览 → 确认入库

优化策略：

- PDF 主/备文本解析，单页失败记录 warning，不让整个批次无解释失败。
- 最多 3 段、单段 6000 字符及文件大小限制，控制上下文成本。
- 对 JSON 围栏、非 JSON、缺字段、题型不合法和重复题干分别处理。
- 文档中的指令性文字只作为数据，降低提示注入对系统提示的干扰。
- 图片和无文字层扫描件明确提示“图片识别暂未开放”，不伪装 OCR 或多模态能力。

### 4.2 检索增强问答（RAG）

当前演示问答采用**班级隔离的关键词检索**：从问题提取有限关键词，在当前班级的知识切片正文和文档名中匹配，选取切片拼接为上下文，再由模型组织回答，并按真实命中文档生成来源标签。

这是“检索 + 生成”的 RAG 结构，但当前 `retrieve_chunks` 未调用向量数据库。Qdrant 仅作为扩展组件与健康探针保留，后续可替换为向量/混合召回，不能把当前实现写成已完成向量检索。

优化策略：

- 班级 ID 强制过滤，防止跨班资料串用。
- 来源列表按文档去重；没有真实命中时不展示虚构来源。
- 答题助手加入题目上下文，提示只给思路和知识点，不直接完成正在作答的作业。
- 检索失败不阻断基础引导，模型失败返回可读降级信息。

### 4.3 ModelRouter 与输出预算

通用 ModelRouter 按配置顺序尝试 provider，具备：

- 无 key 跳过、错误分类、顺序降级与 JSON 审计。
- 连续失败达到阈值后短时熔断，窗口结束自动复位。
- 返回实际 provider/model 与 degraded 状态，界面区分 AI 和模板兜底。

QQ 群聊在通用路由基础上使用多 provider 竞速，以先返回的有效答案为准；并设置整体等待上限、回复字符硬上限和 max tokens 上限。当前配置为 6 秒、300 字、700 tokens；balanced + 200 字的一次真实 LLM 批次约 2.27 秒返回有效答案，该数据不外推为稳定 SLA。

### 4.4 AI 判分、讲评与人工复核

- 单选、多选、判断采用确定性规则。
- 填空支持 strict、smart、ai 三档；语义判分由独立 Jev 适配器完成，具备超时、传输降级及通用 LLM/确定性兜底。
- 判分记录包含依据和降级信息；异常或需人工判断的结果保留教师复核入口。
- AI 讲评与官方解析分区展示，模板内容明确标识，不冒充模型生成。
- 讲评有缓存、超时和流式失败兜底，前端按纯文本清理结果，不将未净化 AI 内容直接注入 HTML。

## 5. 核心功能实现

### 5.1 教师侧

- 班级与学生管理、题库分类、资料上传、组卷发布、提交概览和复核。
- 工作台优先展示待复核、最近提交与未交任务，减少统计查找成本。
- 班级归档后主要写链路被拦截，历史数据仍可读取；学生停用保留历史作答。

### 5.2 学生侧

- 学习首页聚焦待办任务；作答页支持进度、答题卡和草稿恢复。
- 结果页支持错题筛选、官方解析和 AI 讲评；来源与降级状态可见。
- 生长轨迹将经验、等级、连击和活动热力图作为学习反馈，而非替代教学任务。

### 5.3 账号安全

- 密码统一为 8–32 位且包含字母和数字。
- 教师重置本班学生密码时系统生成一次性临时密码，只返回一次；学生登录后强制改密。
- 改密、停用、归档等操作通过 `auth_version` 撤销旧会话；后端拦截强制改密前的普通业务请求。
- 操作审计不记录密码、密码哈希或 token。

### 5.4 QQ 机器人

- 普通 @机器人“帮助、作业、成绩”属于被动回复，可作为稳定演示主线。
- 主动作业通知保存 `sent/failed/skipped`、原因、错误码、错误信息、尝试次数和最后尝试时间。
- 权限错误如 QQ `40034105` 归类为 `qq_permission_denied`；教师显式重试不重复创建通知、不重新发布试卷。
- 当前前端尚未接通知详情与重试按钮，因此不把“页面一键重试”作为已交付功能。

**部署事实：QQ 主动群通知与普通 @ 回复使用不同权限。群主需要在最新版手机 QQ 中开启“机器人主动在群聊内发言”，之后教师发布作业，系统才能自动同步到班级群。** 若现场失败，展示真实权限原因并使用 `@机器人 作业` 继续，不伪造群消息。

## 6. 创新说明

### 6.1 技术创新

1. **AI 与教学数据链结合**：题库结构化、检索问答、语义判分和讲评共享班级上下文，结果可追踪到预览、来源、判分依据或降级状态。
2. **可控可靠性**：ModelRouter 顺序降级与熔断、QQ 竞速与输出预算、Jev 独立适配、模板兜底标识共同构成多层故障隔离。
3. **人机协同而非全自动替代**：AI 负责初筛、初判与解释，教师保留预览确认和复核权。
4. **真实状态建模**：QQ 主动通知不仅记录成功/失败，还保留结构化原因和尝试次数，为权限诊断与重试提供依据。

### 6.2 应用创新

- 把网页教学闭环延伸到学生常用的 QQ 入口，同时保留账号与班级隔离。
- 让学生看见“出处、讲评、下一步”，让教师看见“待复核、未交和学情”，减少 AI 展示与教学行动之间的断层。
- 账号、班级、归档、停用和通知共同服务于轻量级真实班级，而非平台级复杂后台。

## 7. 测试、部署与安全

### 7.1 当前验证结果

| 项目 | 结果 | 口径 |
|---|---|---|
| 后端全量 | 134 passed，1 warning | 本地测试环境 |
| QQ/AI 目标回归 | 10 passed | 0012 迁移后复跑 |
| 前端 | typecheck/build 通过 | 生产构建 |
| 对比度 | 42/42 | 明暗主题自动检查 |
| v1.5 浏览器 | 33/33 | 自包含假响应夹具，非真实 MySQL 全流程 |
| 契约镜像 | SHA256 一致 | 前后端类型文件 |
| Docker MySQL | 0012 为 head | 已备份、迁移并核验字段 |
| 真实主动群通知 | 待现场彩排 | 未验收前不宣称完整通过 |

### 7.2 部署与迁移

- 使用 `deploy/docker-compose.yml`，开发叠加 `docker-compose.dev.yml`。
- 上线前先备份目标数据库，再执行 `alembic upgrade head`；不能仅因容器健康就跳过迁移。
- 当前 Docker MySQL 已从 0011 升至 0012，13 条历史通知保留；其他目标环境仍需分别核验。
- 独立演示 SQL 只作用于指定演示库，不重置现有业务库。

### 7.3 安全与隐私

- `.env` 不入库，`.env.example` 只保留占位符；AppSecret、数据库密码和 token 不写日志或演示材料。
- QQ openid 不在公开 SQL 中写死，演示视频不展示完整 openid。
- 角色、班级归属、归档/停用状态在后端校验，不能仅依赖前端隐藏入口。
- AI 输出纯文本清理，既有 Markdown 出口继续使用 DOMPurify。

## 8. 总结与展望

SproutLearn 已形成“资料—练习—反馈—复核—学情—QQ 触达”的可运行闭环。项目的重点不是堆叠模型名称，而是让 AI 在真实教学流程中有来源、有边界、有降级、有人审。

后续计划：

1. 用真实课堂样本评估检索命中、判分一致性和教师节省时间，形成可量化指标。
2. 在保持班级隔离和来源可解释的前提下，引入向量/关键词混合召回与重排。
3. 完善通知详情和教师重试 UI、真机软键盘与真实 MySQL 全流程 UI 回归。
4. 扩展可解释学情分析和更细粒度权限治理；不以未经验证的自主 Agent、OCR 或商业数据作为宣传点。
