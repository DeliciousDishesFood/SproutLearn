## 1. 全局约定

### 1.1 地址与代理

- 所有业务接口统一前缀：`/api/v1`
- 开发环境前端：`http://127.0.0.1:5174`（新项目端口，避开旧前端 5173）
- Vite 代理：`/api` → `http://127.0.0.1:8000`；`/health` → 同目标
- 也可用 `VITE_API_BASE_URL=http://127.0.0.1:8000` 直连；生产环境同源 `/api`
- 健康检查：`GET /health`、`GET /api/v1/health`（后者不进 OpenAPI）

### 1.2 统一响应信封

所有业务响应都是：

```ts
{
  code: number
  message: string
  data: T
  request_id: string
  timestamp: string
}
```

- `code === 0` 表示成功。
- 前端 `client.ts` 的响应拦截器必须在 `code === 0` 时**自动解包 `data`**，业务层只拿裸数据。
- `code !== 0` 抛 `ApiError`，保留 `code / message / data / request_id / http_status`。
- 422 校验错误也走同一信封，`data` 是字段错误数组；不要按 FastAPI 默认 `detail` 解析。
- 分页统一：

```ts
{ total: number, page: number, page_size: number, list: T[] }
```

### 1.3 鉴权

- 登录后拿到 `data.token`，之后所有受保护请求带 `Authorization: Bearer <token>`。
- token 存 `localStorage`；当前用户存 `localStorage`，但以 `GET /auth/me` 为准。
- 角色：`teacher` / `student`；教师和学生接口互斥，学生调教师接口返回 `40301`，跨班返回 `40302`。
- 收到 `40101` / `40102` 时清 token 并跳登录；登录/注册/加入页请求不要触发全局跳转。
- `POST /binding/qq` 只允许机器人服务端带 `X-Bot-Secret` 调用，**前端不得调用**。

### 1.4 字段口径

- 全部 `snake_case`；禁止组件内改成 camelCase。
- 主键都是 `number`（后端整型）。
- 时间都是字符串；空值为 `null`。`server_now` 是服务端本地时间，倒计时以它为准，不信任浏览器时钟。
- 金额/分数都是 `number`；`total_score`、`full_score`、`score` 保留两位。
- 分页参数统一 `page`（从 1 开始）、`page_size`；后端上限 100。
- 布尔字段一律 `boolean`，不要用 0/1。

## 2. 接口总表（`/api/v1`）

> 角色：P 公开；T 教师；S 学生；T/S 按角色分流；B 仅机器人服务端。  
> 返回类型中的 `Paged<T>` 即统一分页结构。

| POST | `/auth/teacher/register` | P | `TeacherRegisterPayload` | `AuthResult` |

| POST | `/auth/logout` | T/S | 无 body | `null` |

### 2.6 试卷 `papers.py`

| 方法 | 路径 | 角色 | 关键参数 | 返回 |
|---|---|---|---|---|
| POST | `/classes/{class_id}/papers` | T | `PaperCreatePayload` | `PaperDetail` |
| GET | `/classes/{class_id}/papers` | T/S | `page, page_size` | `Paged<PaperItem>` |
| GET | `/papers/{paper_id}` | T | 无 | `PaperDetail` |
| PATCH | `/papers/{paper_id}` | T | `PaperUpdatePayload` | `PaperDetail` |
| PATCH | `/papers/{paper_id}/withdraw` | T | 无 | `PaperDetail` |
| POST | `/papers/{paper_id}/publish` | T | 无 | `PaperPublishResult` |

- `GET /papers/{paper_id}` 是**教师视角**，包含 `questions[].answer` 与 `analysis`；学生不得调用。

- `PaperCreatePayload` 支持 `kind`、`due_at`；`PaperUpdatePayload` 支持 `title / duration_minutes / blank_mode / kind / due_at`。
- `due_at` 是**试卷截止时间**；`deadline_at` 是**单次作答倒计时截止**，两者不能混用。

### 2.7 作答 `attempts.py`

| 方法 | 路径 | 角色 | 关键参数 | 返回 |
|---|---|---|---|---|
| GET | `/attempts/mine` | S | `page, page_size` | `Paged<MyAttemptItem>` |
| GET | `/attempts/{attempt_id}` | T/S | 无 | `AttemptResume` |
| PUT | `/attempts/{attempt_id}/answers/{question_id}` | S | `{ answer: unknown }` | `AnswerSaveResult` |
| POST | `/attempts/{attempt_id}/ask` | S | `AskSproutRequest` | `AskSproutResponse` |
| POST | `/attempts/{attempt_id}/submit` | S | 无 | `AttemptResult` |
| GET | `/attempts/{attempt_id}/result` | T/S | 无 | `AttemptResult` |
| POST | `/attempts/{attempt_id}/reviews` | T | `{ answer_record_id, new_score, comment? }` | `AttemptResult` |

**恢复作答 `AttemptResume`**：`attempt`、`paper`、`questions[]`、`answers`（key 为 question_id 字符串）、`server_now`、`remaining_seconds`。  
- 学生视角 `questions[]` 不含 `answer` / `analysis`。
- `paper.kind` 稳定下发；`remaining_seconds=null` 表示无时限，`0` 表示已截止或已提交。

**提交/结果 `AttemptResult`**：`attempt`、`paper`、`answers[]`、`reviews[]`、`grading_ms`。  
- `answers[]` 含 `standard_answer`、`analysis`、`raw_answer`、`score`、`is_correct`、`needs_review`、`detail`。
- 学生只能在 `attempt.status` 为 `submitted/graded` 后调用结果接口；后端 P0 必须拦截 `doing` 状态。

**问问小芽 `AskSproutRequest`**：

```ts
{
  question_id: number
  selected_text: string   // 最长 500，去空格后不能为空
  message: string         // 最长 500，不能为空
  history: Array<{ role: 'user' | 'assistant', content: string }> // 后端只取最近 6 条
}
```

**响应**：`{ answer: string, sources: Array<{ doc_id: number, doc_name: string }> }`。  
- 仅 `status=doing` 且 `paper.kind=practice` 可用；exam/homework 返回 `40301`。
- 空 `selected_text` 返回 `40001`；3 秒 1 次、每天 40 次，超限 `42901`；LLM 全失败 `50301`。
- `answer` 是纯文本，最多 600 字；前端按纯文本渲染，不注入 HTML。

### 2.8 工作台/成长 `workbench.py`

| 方法 | 路径 | 角色 | 关键参数 | 返回 |
|---|---|---|---|---|
| GET | `/me/workbench` | S | 无 | `StudentWorkbench` |
| GET | `/classes/{class_id}/workbench` | T | 无 | `TeacherWorkbench` |
| GET | `/me/activity` | S | `weeks=1..52` | `ActivitySummary` |
| GET | `/classes/{class_id}/activity` | T | `weeks=1..52` | `ActivitySummary` |
| GET | `/me/growth` | S | 无 | `GrowthSummary` |
| GET | `/classes/{class_id}/xp-config` | T | 无 | `XpConfigResponse` |
| PATCH | `/classes/{class_id}/xp-config` | T | `{ items:[{code,enabled}] }` | `XpConfigResponse` |
| GET | `/quotes/random` | P | `type?` | `QuoteResult` |

**教师工作台语义（必须按此展示，不能改标签）**：
- `pending_review`：**待复核题目数**（answer_record 计数），不是“待批作业份数”。
- `today_submissions`：今天提交的作答数。
- `active_students`：今天有答题记录的去重学生数。
- `average_score`：已提交/已复核作答的原始平均分；`average_score_rate` 是 0~1 的平均得分率，展示百分比时用后者。
- `recent_papers`：最近 5 份试卷，`PaperBrief[]`。
- `top_students` / `top5`：同值，按 XP 前 5。
- `activity`：12 周班级活动，元素 `{date, answers, active_students}`。

**学生工作台**：
- `pending` / `pending_papers` 同值；`recent` / `recent_scores` 同值。
- `today` 是今日 XP 明细，`cap` 是练习日封顶。
- `level` 是等级进度，`progress_pct` 0~100。

**活动**：`items` 与 `activity` 同值；日期为 `YYYY-MM-DD`，默认 12 周 = 84 天。

**金句**：永远 `200`，`{ text, from, source }`；`source` 可能是 `shiora / hitokoto / local`。

## 4. v1 冻结结论：新增接口 = 0

### 4.1 明确不新增 endpoint

board-ui 需要的以下板块，用现有接口即可完成：

- 工作台统计卡：`TeacherWorkbench` 四个指标。
- 最近试卷表：`TeacherWorkbench.recent_papers`。
- 学习热力：`class_activity` / `student_activity`。
- 班级表格、学生表格：`classes` / `students`。
- 试卷表、批改表：`classes/{id}/papers` → `papers/{id}/attempts` → `attempts/{id}/result`。
- 学生待办、成绩：`me/workbench`。
- 练习 + 问问小芽：`attempts` + `ask`。
- 通知、文档、机器人设置：现有接口。

因此 **v1 不新增 `/review-queue`、`/students/{id}`、`/me/bootstrap`、`/search`、`/paper-stats`**。  
这些是候选，不是本版契约；新前端不得依赖、不得 mock 成“已实现”。若下一版确实需要，另开 v2。

### 4.2 后端必须补的 2 个 P0 行为/字段

这两项不改变 endpoint 路径，只让契约与真实数据一致；新前端可以先按契约写，后端未完成时按 `null` 兜底。

**B0｜结果接口越权拦截（安全，必须做）**

- `GET /attempts/{attempt_id}/result` 当前对 `doing` 状态也返回 `standard_answer` / `analysis`，学生可在提交前看到答案。
- 契约要求：当 `current.role === "student"` 且 `attempt.status === "doing"` 时返回 `40910`，message「本次作答尚未提交，不能查看结果」。
- 教师仍可查看（教师本来就有试卷标准答案）。
- 文件：`backend/app/services/attempt_service.py` 的 `get_result`；补测试 `backend/tests/test_attempt_result_guard.py` 或既有 attempt 测试文件。

**B1｜工作台精简试卷补 `due_at`**

- `TeacherWorkbench.recent_papers` 与 `StudentWorkbench.pending` 走 `_paper_brief`，当前不含 `due_at`；学生首页无法显示截止时间。
- 契约要求：`_paper_brief` 增加 `"due_at": fmt_dt(paper.due_at)`。
- 文件：`backend/app/services/workbench_service.py`；补测试断言 `pending[0].due_at` 存在且可为 `null`。
- 已有 `PaperItem` 已含 `due_at`，无需改 `paper_service._paper_item`。

### 4.3 可选但不在 v1 的候选（禁止本轮实现）

| 候选 | 为什么不做 |
|---|---|
| `GET /classes/{id}/review-queue` | 批改页可用“试卷 → 作答列表 → 结果”三级下钻完成；新增会扩大后端面 |
| `GET /classes/{id}/students/{student_id}` | 学生表格现有字段已够；下钻不是 P0 |
| `GET /me/bootstrap` | 前端可并行请求；首屏 2~3 个请求可接受 |
| `GET /search` | board-ui 的搜索可先做当前页客户端过滤，不做全局搜索 |
| `GET /papers/{id}/stats` | 批改页用已有 attempts 计数，不做统计接口 |

## 5. 权限与状态机

### 5.1 权限矩阵

| 资源 | 教师 | 学生 |
|---|---|---|
| 班级 | 仅自己创建的班级 | 仅自己 `class_id` |
| 学生列表 | 本班 | 不可调用 |
| 知识库/题库/题目 | 本班 | 不可调用 |
| 试卷详情 `GET /papers/{id}` | 本班 | 禁止（教师视角含答案） |
| 班级试卷列表 | 本班全部状态 | 本班仅 published |
| 开始作答 | 禁止 | 本班 published |
| 恢复作答 | 本班学生 attempt | 仅自己 attempt |
| 保存答案/提交/ask | 禁止 | 仅自己 doing attempt |
| 结果 | 本班 attempt | 仅自己 submitted/graded attempt |
| 复核 | 本班 attempt | 禁止 |
| 通知 | 自己 | 自己 |
| 机器人配置 | 本班 | 禁止 |

### 5.2 试卷状态

- `draft`：可改 `title / duration_minutes / blank_mode / kind / due_at`；可发布。
- `published`：不可改内容；可撤回为 `closed`；学生可见、可开卷。
- `closed`：可重新发布；学生不可见（列表只返回 published）。

### 5.3 作答状态

- `doing`：可保存答案、可 ask（仅 practice）、可提交；结果接口必须被后端拦截。
- `submitted`：可看结果、待复核；不可改答案。
- `graded`：教师已复核；可看结果。

### 5.4 问问小芽边界

- 仅学生本人、同班、`doing`、`paper.kind === "practice"`。
- `selected_text` 2~300 字是前端触发范围；后端允许 1~500 字，空串 400。
- 前端必须保留 `question_id`、`selected_text`、`message`、最近 6 条 `history`。
- 回答按纯文本渲染；不把 `answer` 当 HTML/Markdown 注入。
- 限流：3 秒 1 次/学生，日 40 次；429 时按钮禁用并提示，不自动重试。

## 6. 前端实现约束（契约级）

1. **目录**：新建 `frontend-v3`，不修改 `frontend/`；旧前端保留可运行。
2. **技术栈**：Vue 3 + Vite + TypeScript + Vue Router + Pinia + Axios，依赖复用旧 `frontend/package.json` 的版本；不新增 Tailwind、Board UI 包、组件库、字体、网络资源。
3. **HTTP 层**：必须实现统一信封解包、Bearer 注入、401 清会话、`ApiError`；不得每页自己写 `fetch` 解析。
4. **类型**：以 `contract-types.ts` 为准；可复制到 `frontend-v3/src/api/contract.ts` 并只做路径/导入调整，不得改字段名。
5. **路由守卫**：按 `auth.me.role` 分流；教师不能进学生页，学生不能进教师页；无班级教师进“创建班级”空态。
6. **教师工作台**：统计卡标签按 §2.8 语义；没有数据的卡显示 0 + 空态，不伪造环比。
7. **图表**：精确数值用表格在上；热力点阵/柱状条只做结构展示，图内不重复堆数字。
8. **练习页**：选区触发“问问小芽”只在题干/选项容器；忽略 input/textarea/contenteditable；exam/homework 不渲染入口；不遮蔽提交栏。
9. **视觉**：只用 board-ui 青柠 token（见派工包 §4）；不做全页泛绿、不用深绿主色、不做玻璃拟态/新拟物。
10. **提交/发布/删除**：前端必须二次确认；失败保留表单；不自动重试写操作。
11. **未联调不伪报**：后端未启动时，只能声明“按契约实现 + typecheck/build 通过”，不能写“端到端通过”。
