## 0. 结论

1. **契约对齐总体成立**：已抽查的 API 封装与契约路径、方法、主要字段一致；未发现新增 endpoint、改名或自造字段。学生 `doing` 看结果 `40910`、`due_at` 可 `null`、学生不调 `GET /papers/{id}` 等关键边界在代码层有对应处理。
2. **存在 1 个高风险的答案丢失竞态**：`AttemptView` 自动保存先删 pending、再发请求，提交时不等在途请求；保存失败也不阻断提交。该问题已由代码确认，不是推测。
3. **你指出的两个 UI 问题都成立，且根因明确**：badge 不是 `BaseBadge` 自身的问题，而是 `.table__row` 的 grid item 默认 `stretch` + flex 默认 `flex-start`；热力图不是“少一个 tooltip”，而是 12 列 × 7 行被 `space-between` 拉散、数据按日期横向排、只按 `answers` 着色、没有统计/月份/可访问状态。
4. **另有若干功能/口径缺口**：发布按钮在详情加载前可见、知识库 accept 漏 PPT、多处分页固定 50 且计数不是 `total`、固定组卷只能看到前 50 题、题目筛选/编辑字段不完整、API baseURL 与 SSE 前缀可能不一致、HTTP 200 信封错误绕过全局会话处理、机器人“测试连通性”会覆盖未保存表单、学生点了“作业已发布”通知只高亮不进入试卷。
5. **建议本轮只派前端修复，后端零任务**。所有修复都能在冻结 v1 契约内完成；不要新增 `/review-queue`、单题创建等契约外 endpoint。题目“单题新建”本来就不是 v1 契约能力，P13 的“新建”表述不准确，页面应明确只保留“导入题目”。

### 2.1 客户端偏差（不是字段改名）

- `src/api/client.ts:62` 用 `VITE_API_BASE_URL ?? '/api/v1'`；`src/utils/constants.ts:21-26` 的 `API_BASE_URL` 对 `/api/v1` 会再拼一次 `/api/v1`。HTTP 与 SSE 因此可能走不同前缀（R10）。
- `client.ts:118-146` 在 fulfilled 分支对 `body.code !== 0` 直接 `throw ApiError`，不会进入同一个 interceptor 的 rejected 分支；`40101/40102` 若以 HTTP 200 信封返回，不会触发 `clearSession`/`SESSION_EXPIRED_EVENT`/全局 toast（R11）。

### 2.2 P13 表述纠正

- P13 声称“题目新建/编辑/删除/导入”已落地，但 v1 契约只有导入两步、`PATCH /questions/{id}`、`DELETE /questions/{id}`，**没有 `POST /classes/{id}/questions` 单题创建**。当前页面也没有单题新建入口，这是正确的；应把 P13 的“新建”改为“导入/管理题库”，不要为了对齐报告而新增契约外接口。
- P13 的 `npm run check:ui` 属于旧前端脚本，`frontend-v3/package.json` 没有该 script；新前端验收只认 `typecheck`/`build` + 浏览器走查。

#### R1 细目（badge）

- 目标对齐：与表头“状态/得分”右对齐，`justify-self: end`；若产品要求列中心，改 `center`，但不要既 `stretch` 又 `flex-start`。
- 验收：1440/1024/375 下，badge 外框宽度 = 文本 + 左右 padding，不再占满 76px；文字水平/垂直居中；通知、状态 badge 不受影响。
- 不建议：给 `BaseBadge` 加固定宽度或 `width:100%`；那会把“内容自适应”再次做反。

#### R2 细目（热力图）

**布局**

- 12 列（周）× 7 行（列内连续 7 天），`grid-auto-flow: column`；每列 7 个日期，列内从上到下。
- 固定点尺寸 13px、gap 7px，`justify-content: center`；不要 `space-between`。84 个点总宽约 233px，1440 卡片内居中，375 仍可容纳。
- 移除 `.dots-legend { margin-top:auto }` 的“把图例推到底部”行为；图例与读数条贴近图。

**着色**

- 教师：`answers` 为强度；`active_students` 只进读数，不主导颜色。
- 学生：`xp > 0 ? xp : answers`；这样 `answers=0/xp>0` 的登录/奖励日不再显示 l0。
- 0 值始终 l0；`max` 用当前角色强度字段；比例分档 0 / ≤25% / ≤50% / ≤75% / >75%，对应 l0–l4。
- 不要用 `active_students` 做教师强度：它衡量“人数”，不衡量“答题量”，会把少量答题但多人在线的日子误染深。

**统计（图上方，教师/学生不同）**

| 角色 | 统计项 | 数据来源 |
|---|---|---|
| 教师 | 12 周总作答、活跃天数（`answers>0`）、单日最高作答、今日活跃学生（最后一天 `active_students`） | `ActivityDay[]` |
| 学生 | 12 周累计 XP、活跃天数（`xp>0 || answers>0`）、单日最高 XP、今日 XP（最后一天 `xp`） | `ActivityDay[]` |

- 只使用真实字段，不造“连续学习天数”等契约没有的指标；学生“连续学习”在 `StudentWorkbench.streak_days` 已有，但热力卡不要重复造。
- 数值为 0 时显示 0，不显示“—”或假数据。

**悬浮/聚焦/点按状态**

- 每个点渲染为 `<button type="button" class="heat-cell">`，带 `aria-label`（日期、星期、作答数、教师 `活跃学生`/学生 `XP`、档位）。
- 悬停/聚焦/点按更新图下方或图上方的 `aria-live="polite"` 读数条；不要只依赖原生 `title`。
- 键盘：容器 `tabindex="0"`，左右箭头按周移动（±7），上下箭头按天移动（±1）；roving tabindex，只有当前格可 Tab。
- 触屏：点按即选中并显示读数条，不做跳转；本轮不需要点击进入某天详情。

**月份**

- 不硬编码 `9/10/11`；按每列首日计算月份，月份变化时输出 `8月/9月/10月/11月`。
- 12 列网格下方用同一列模板渲染标签；标签允许 `span 2`，但不得挤出卡片。
- 当前 2026-11-15 的 12 周窗口约为 8 月下旬到 11 月中，实际标签应随数据生成。

**父级**

- `DashboardView.vue`、`student/HomeView.vue`、`student/GrowthView.vue` 的 `<HeatDots>` 增加 `role="teacher"` / `role="student"`。
- 卡片标题保留“最近 12 周”；不要把统计塞进 `<header>` 的 `card__meta` 导致换行挤压。
- `GrowthView` 的“图内只展示活跃结构”改为“悬停查看每日经验”，避免自相矛盾。
