### 五、风险

1. **全量 ruff 基线未清零**：221 处历史 lint 分布在本轮未被允许改动的文件（`app/` 多处路由/服务、`tests/` 既有用例、`scripts/probe_llm.py`）。本轮只保证触及文件干净；按边界未越界批量修复。建议另开一个独立任务，先确定项目拟启用的 ruff 规则集（仓库当前无 `ruff.toml` / `pyproject.toml` 配置，B008 等规则对 FastAPI 属惯用法误报，宜在配置里显式忽略或豁免），再分批收敛。
2. **教师例外语义**：`get_result` 只拦截学生 `doing`；教师看 `doing` 仍 200（教师本就持有标准答案）。前端教师端不要把这条 200 误判为学生越权。
3. **`due_at` 空值兜底**：无截止日期返回 `null`，前端必须按空态处理，不能渲染成 `Invalid Date` 或 `"None"`；后端不补默认文案。
4. **状态边界**：学生在 `submitted` / `graded` 可看结果，`doing` 被拦截；若后续业务把可看状态收紧到仅 `graded`，需同步调整 `get_result` 判断与本批测试。
5. **测试环境与生产差异**：回归跑在 SQLite + fakeredis 上，未连真实 MySQL80 / Redis；判分、问问小芽、限流等链路的真实行为未在本轮覆盖。
6. **时间格式**：`due_at` 沿用 `fmt_dt` 的服务器时区与 `YYYY-MM-DD HH:mm:ss` 格式；跨时区部署时以后端 `fmt_dt` 为准，前端不要自行换算改写字段。
7. **依赖安装**：`requirements.txt` 全部锁定版本在 Python 3.13.18 上安装成功，无源码编译失败、无弃用包；venv 与日志均落在仓库外 `C:\Users\OMEN\venvs\sproutlearn-backend`。
