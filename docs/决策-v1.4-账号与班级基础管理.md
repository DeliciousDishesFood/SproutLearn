# 决策：v1.4 账号与班级基础管理——必须做 / 可暂缓 / 不做

日期：2026-11-16
定位：QQ 演示检查点之后的独立小版本，不混入登录/答题 UI 美化，不扩成平台后台。

## 一、结论

用户转述的密码缺口基本成立：当前认证路由只有注册、登录、登出、`/auth/me`；学生与教师模型没有密码状态字段；文档列表当前没有角色过滤。它们属于真实安全与管理闭环，不是锦上添花。

但“必须做”不等于“明天 QQ 录制前必须做”。本次先提交并保留 QQ 演示检查点，账号与班级管理随后按 v1.4 独立实施。

## 二、必须做

| 优先级 | 项目 | 决策 | 原因 |
|---|---|---|---|
| P0 | 统一密码规则 | 注册、入班、改密、临时密码校验统一为 **8–32 位，至少含字母和数字**；错误文案一致 | 当前前端“至少 6 位”与后端规则不一致，是明确契约缺陷 |
| P0 | 学生自助改密 | 验证当前密码；新密码不得与当前密码相同；成功后旧会话全部失效并重新登录 | 基本账号能力 |
| P0 | 教师重置学生密码 | 只能重置本班学生；系统生成一次性随机临时密码，只展示一次；教师不能指定或查看原密码 | 固定全班弱密码容易被同班冒用 |
| P0 | 临时密码强制改密 | 学生持临时密码登录后，后端仅放行 `/auth/me`、改密、登出；其他业务统一拒绝 | 只靠前端路由不是安全控制 |
| P0 | 按用户撤销全部会话 | 重置/改密/停用学生后，所有设备旧 token 立即失效 | 只更新 `password_hash` 不影响已签发 token |
| P0 | 最小操作记录与限流 | 记录操作者、目标、班级、时间、结果；不记密码/hash；重置与改密限流 | 防连续点击与恶意重置；无需另做审计中心 |
| P0 | 学生文档按角色过滤 | 列表和详情都在后端过滤；QQ 配置、教师导题等运维文档学生不可见，直接猜 slug 也返回 404 | 权限不能只靠前端隐藏 |

### 推荐安全模型

在 `teacher`、`student` 增加：

- `must_change_password: boolean/tinyint`，默认 0；
- `auth_version: int`，默认 1。

JWT/session 增加 `auth_version`。每次鉴权核对数据库当前值：

- 教师重置学生：学生 `auth_version += 1`、`must_change_password = 1`，临时密码只存 hash。
- 学生改密成功：`auth_version += 1`、`must_change_password = 0`，清本地会话并跳登录。
- 教师改密成功：教师 `auth_version += 1`，其他会话失效。
- 停用学生：`auth_version += 1`，旧 token 即使仍在 Redis 也不能通过鉴权。

这样无需维护“永久准确的设备列表”，Redis 会话删除可作为优化，数据库版本号是最终防线。

## 三、要做，但排在密码闭环之后

| 优先级 | 项目 | 轻量实现边界 |
|---|---|---|
| P1 | 教师修改自己的密码 | 复用学生改密接口与密码规则；教师设置页增加账号安全，不单独造一套流程 |
| P1 | 学生停用 / 恢复 | 用现有 `student.status`；停用后撤销会话、禁止登录/作答/通知/QQ 查询；保留作答、成绩、XP 与 QQ 绑定；恢复后重新登录，不恢复旧 token |
| P1 | 班级归档 / 恢复 | 用现有 `class.status`；默认列表只看活跃班，归档班独立筛选；归档后禁止新增/修改/发布/通知/QQ，历史数据保留，可恢复；班级上限只计活跃班 |
| P1 | AI 讲评来源与降级标识 | 区分“题目解析 / AI 讲评 / 模板降级 / 服务不可用”；是产品可信性任务，建议另开讲评小版本，不塞进账号迁移 |

归档/停用不做物理删除，不做复杂审批，不做批量管理。

## 四、现在不做

- 邮箱、手机号自助找回密码。
- 全班批量重置密码。
- 独立登录设备管理页。
- 独立审计日志中心（只保留最小操作记录）。
- 平台超级管理员、家长账号、多角色权限系统。
- 密码强度条、历史密码禁止重复等增强规则。
- 固定 `123456` / 全班统一默认密码并允许长期使用。
- 为“撤销会话”另建大型设备/session 微服务。

## 五、实施顺序

1. **B1 契约与迁移**：密码规则、`auth_version`、`must_change_password`、错误码、最小操作日志。
2. **B2 密码闭环**：学生改密、教师重置、强制改密拦截、全会话失效、限流。
3. **B3 权限与账号**：教师改密、文档角色过滤、学生停用/恢复。
4. **B4 班级管理**：归档/恢复、活跃班上限、归档只读规则。
5. **前端同步**：账号安全页、一次性临时密码弹窗、强制改密页、学生行操作、归档班筛选；全部复用 ConfirmDialog/BaseModal。
6. **验收后独立提交**：`feat(v1.4): 补齐账号安全与班级基础管理闭环`。

## 六、不能破坏

- 作答、成绩、XP、等级、知识库、通知历史与 QQ 绑定保留。
- 越权教师不能重置/停用别班学生，不能归档别班班级。
- 不把临时密码写入日志、审计记录或再次查询接口。
- 不在本版本改 QQ 演示 SQL 的账号数据语义；迁移默认值保证既有账号继续登录。
- 不改旧 `frontend/`，主线仍是 `frontend-v3/`。
