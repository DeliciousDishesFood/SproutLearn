## 一、本轮决策

1. **采纳 Kimi 复核。** 当前核心问题是“小、淡、均”＋键盘/焦点/触控/失败出口，不再把视觉换皮当主线。
2. **明天重头改为 QQ 机器人。** 后端已有群绑定、学生绑定、作业/成绩、催交、AI 问答、通知幂等，不重造；补演示数据、真实 worker 预检、完整彩排与备用证据。
3. **数据不再恢复旧班。** 使用新 SQL 在独立 demo schema/数据库生成 1 教师、1 班、10 学生；不碰旧 MySQL，不重置当前 contract.db。
4. **SQL 不只放账号。** 必须有题库、2 份试卷、4 已交/2 作答中/4 未开始、知识库切片、52 周活动和 bot_config，否则 QQ 作业/催交/AI 与热力图都会露空。
5. **离线与在线严格分开。** `test_m34`/handler smoke 通过不等于真实 QQ 在线；只有 token＋READY＋真实群回复才能写“在线通过”。

## 五、QQ 机器人主线（6–8 分钟）

1. 导入校验通过；启动 API 与 worker；日志出现 `qq gateway READY`。
2. 教师网页：保存 QQ 配置 → 测试连通性 → 生成群绑定码。
3. QQ 群：`@小芽 绑定群 <8位>` → 群绑定成功。
4. 学生网页生成绑定码 → QQ `绑定 <8位>` → 绑定学号/班级。
5. 学生 `作业`、`成绩`；教师 `作业`（应见 4/10）、`作业情况`、`催交`。
6. 教师发布一份新作业 → 群内 `【新作业】`；重复操作不刷屏。
7. 学生 `@小芽 TCP 和 UDP 有什么区别？` → 基于知识库回答；追问三次握手。
8. 学生提交 → 教师再查统计，站内通知同步。
9. 备用：主动消息权限失败/@失败/LLM 失败/网关断连都有真实日志与备用截图，不伪装成功。

完整逐句脚本由后端交付 `docs/demo/QQ机器人录制脚本.md`。
