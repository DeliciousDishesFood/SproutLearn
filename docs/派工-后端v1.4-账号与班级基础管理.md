# 派工：后端 v1.4 账号与班级基础管理（DeepSeek 后端窗口）

> 可直接复制给 DeepSeek。先读 `docs/决策-v1.4-账号与班级基础管理.md`。这是 QQ 演示检查点之后的独立版本，不改前端、不改旧 `frontend/`、不提交。

## 一、目标与边界

补齐密码安全、会话撤销、文档权限、学生停用与班级归档。不要做邮箱找回、设备管理页、审计中心、超级管理员、家长账号或批量重置。

基线：当前后端 122 passed；已有 Redis 单 jti 会话、学生/班级 `status`、统一响应和迁移 0001–0010。

## 二、B1 契约、迁移与密码规则

1. 新迁移 `0011_account_class_security.py`：
   - `teacher.auth_version` / `student.auth_version`：非空，默认 1；
   - `teacher.must_change_password` / `student.must_change_password`：非空，默认 0（教师字段用于统一模型，正常注册不强制）；
   - 最小 `account_audit_log`：actor_role/actor_id、target_role/target_id、class_id、action、result、request_id、created_at；不存密码/hash/token。
   - SQLite/MySQL 均可迁移；默认值保证既有账号行为不变。
2. 所有密码入口复用同一规则：8–32 位且同时含字母、数字；包括教师注册、学生入班、学生/教师改密、临时密码生成。
3. 更新 `docs/frontend-v3-contract/00-接口契约-v1.md`、`contract-types.ts`、后端 schema 与 `frontend-v3/src/api/contract.ts` 镜像；两镜像 SHA256 一致。
4. 新错误码集中登记：`40303 PASSWORD_CHANGE_REQUIRED`、`40304 ACCOUNT_DISABLED`、`40305 CLASS_ARCHIVED`；密码相同/规则错误用 40001，不滥加错误码。

## 三、B2 会话版本与鉴权拦截

1. JWT 与 Redis session 保存 `auth_version`；登录签发当前版本。
2. `get_current_user` 必须核对数据库用户的 `auth_version`、`status` 和 `must_change_password`。版本不一致按 40102 会话失效，不能只检查 Redis jti。
3. `must_change_password=1` 时，只允许：
   - `GET /auth/me`；
   - `POST /auth/password/change`；
   - `POST /auth/logout`。
   其他业务统一 40303，前端跳转不能代替后端拦截。
4. 改密、重置、停用都递增 `auth_version`；旧 token 即使仍在 Redis 也必须失效。Redis 删除只做优化，数据库版本是最终依据。
5. `/auth/me` 返回 `must_change_password`；登录响应同样返回，前端据此进入强制改密页。

## 四、B3 密码闭环

### 1. 学生/教师自助改密

`POST /api/v1/auth/password/change`
- body：`current_password`、`new_password`。
- 验证当前密码；新密码规则统一；不得与当前密码相同。
- 成功后更新 hash、`auth_version += 1`、清 `must_change_password`，写最小 audit；返回成功，不返回新 token，用户重新登录。
- 限流：同一用户 15 分钟最多 5 次失败尝试，配置走 settings。

### 2. 教师重置学生密码

`POST /api/v1/classes/{class_id}/students/{student_id}/password-reset`
- 仅本班教师；目标必须是该班学生，跨班返回 40302，不能泄露学生存在性。
- 系统用 `secrets` 生成随机临时密码，满足统一规则且避免易混淆字符；教师不能传入/指定新密码。
- 只存 hash；响应仅本次返回 `temporary_password`，无再次查询接口，不写日志/audit。
- 学生 `must_change_password=1`、`auth_version += 1`；作答/成绩/XP/QQ 绑定不动。
- 限流：同一学生每小时最多 5 次、同一教师每天最多 30 次；配置走 settings。
- 失败也写最小 audit（不含密码）。

## 五、B4 学生停用/恢复

`PUT /api/v1/classes/{class_id}/students/{student_id}/status`，body `status: 0|1`。
- 仅本班教师；停用递增 auth_version，所有旧会话失效。
- 停用后禁止登录、作答、通知、QQ 作业/成绩/AI 命令；保留历史数据与 QQ 绑定。
- 恢复后允许重新登录，旧 token 不恢复；不重置 XP/作答。
- 幂等：重复设置相同 status 不重复递增 auth_version，返回当前状态。

## 六、B5 班级归档/恢复

`POST /api/v1/classes/{class_id}/archive`、`POST /api/v1/classes/{class_id}/restore`。
- 仅班级所属教师；用现有 `class.status`（1 活跃、0 归档），不物理删除。
- 默认班级列表只返回活跃班，支持 `include_archived=true` 或明确筛选参数；班级上限只计活跃班。
- 归档后禁止新建/修改题库、发布/撤回试卷、发送通知、QQ 查询与催交、学生登录和新作答；历史详情/成绩可读。
- 归档不写 BotNotice，不伪造通知成功；worker 遇到归档班友好提示。
- 恢复后回到活跃状态，不恢复任何已撤销会话；重复归档/恢复幂等。
- 将活跃校验集中进班级依赖/服务守卫，避免逐路由漏判。

## 七、B6 文档角色过滤

- `content/docs/manifest.json` 增加 `roles`，默认 `['teacher','student']`；QQ 配置、教师导题等标为 `['teacher']`。
- `list_docs(role)` 与 `get_doc(slug, role)` 都在后端过滤；学生直接请求教师 slug 返回 40401。
- 同步路由、schema 和测试，不靠前端隐藏。
