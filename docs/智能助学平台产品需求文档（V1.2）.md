## 1. 产品概述

### 1.1 定位

面向上课场景的班级级教学辅助系统，一个班一位教师、若干学生，围绕「教师上传的课程资料」形成可控的知识闭环。与通用大模型产品的核心区别是**答案有出处**：所有问答与试题讲解建立在教师自己上传的课程资料之上，不依赖模型的通识记忆。

### 1.2 核心目标

1. 减少教师重复劳动：组卷、答疑、客观题判分交给系统，教师只保留出题意图与主观题终审。
2. 让学生拿到有依据的答案：问答必须可追溯到知识库原文。
3. 把提醒推送到学生已在的地方：QQ 群机器人覆盖发布、截止提醒与个人进度查询。
4. 用成长体系维持练习动力：经验值与等级头衔承接刷题、作业等行为。

### 1.3 交付约束（✅ 已决，R1-1）

| 项 | 约束 |
|---|---|
| 目标赛事 | AI Web 赛道 |
| 开发模式 | 人工主导 + AI 编程加速；全程可介入调参 |
| 交付周期 | 2026-11-07 ～ 2026-11-18（10 个开发日 + 1 天缓冲 + 提交日） |
| 一期唯一基准 | 最小可演示闭环 + 1 个 AI 亮点 |
| 工程约束 | 禁止死编码：检索策略、判分器、机器人能力三层均为「策略接口 + 配置开关」，二/三期只加实现不改主干 |

### 1.4 一期明确不做

- 不做多学校、多机构入驻，只做单校多班级的班级级隔离。
- 不做知识图谱（KAG），二期评估后再投入。
- 不做主观题全自动判分闭环：AI 结果必须经教师确认才计入成绩。
- 不做移动端原生 App，一期保证 PC 浏览器可用与移动端网页基础可用。
- 不做技术防作弊（切屏检测、禁止复制、锁浏览器）。
- 不做内置演示数据初始化功能（改由独立脚本提供，见附录 B）。
- 不做平台管理员角色（教师即班级最高权限人）。

## 3. 角色、账号与权限

### 3.1 角色（✅ 已决，R1-2）

| 角色 | 定位 | 核心权限 |
|---|---|---|
| 教师 | 班级唯一管理者与数据所有者 | 创建班级、知识库管理、题库与考试发布、标准答案修改、主观题终审、机器人绑定与查询项开关、成长规则开关 |
| 学生 | 本班内容消费者，权限受教师开关控制 | 本班知识库提问、参加考试与练习、错题本、查看本人成绩与经验等级、群内 @ 查询被授权信息 |

**无平台管理员角色。** 教师即其班级的最高权限人。

### 3.2 账号体系

> 【修改】班级相关标识拆分为两个，职责不得混用：**班级编号 `class_code`＝身份**，创建即生成、永久不可修改，用于学生登录定位班级；**邀请码 `invite_code`＝入场券**，用于新生加入班级，可重置、可失效，加入后不再参与登录。

| 环节 | 规则 |
|---|---|
| 教师注册 | 邮箱或手机号 + 密码自助注册；注册后可创建多个班级 |
| 班级 | 【修改】创建时生成班级编号 `class_code` 与邀请码 `invite_code`；两者均为大写字母 + 数字，排除易混字符 O/0/I/1 |
| 班级编号 | 【新增】`class_code` 创建班级时生成，永久不可修改、永不重置；长度由 `CLASS_CODE_LENGTH` 控制（默认 6，可配 8）；字符集大写字母 + 数字，排除 O/0/I/1；仅用于学生登录定位班级 |
| 邀请码 | 【新增】`invite_code` 为 6 位大写字母 + 数字，排除 O/0/I/1；可重置，重置后旧码立即失效；只作为新生加入班级的「入场券」，不参与登录 |
| 学生加入 | 【修改】邀请码 `invite_code` + 学号 + 自设密码；同一班级内学号唯一；加入成功后获得该班 `class_code` |
| 学生登录 | 【修改】班级编号 `class_code` + 学号 + 密码；不再使用邀请码；教师重置邀请码不影响已加入学生登录 |
| 教师登录 | 账号密码；Redis 维护会话，30 分钟无操作过期 |

**学生登录流程（【修改】）**

1. 学生输入 **班级编号 `class_code` + 学号 + 密码**。
2. 系统按 `class_code` 定位班级，再以「班级 + 学号」校验账号与密码。
3. 校验通过后签发会话，会话携带所属 `class_id`；此后所有数据访问按班级隔离。
4. 邀请码 `invite_code` 只用于「加入班级」环节，加入后不再参与登录；教师重置邀请码不改变班级编号，也不影响已加入学生登录。

### 3.3 QQ 身份绑定（✅ 已决，R1-2）

1. 学生在个人中心生成 8 位一次性绑定码（有效期 10 分钟）。
2. 学生在绑定的班级群内 @ 机器人，发送「绑定 8位码」。
3. 机器人校验绑定码与班级归属，写入 `qq_binding` 表（一个 QQ 号只绑定一个学号，可解绑）。
4. 未绑定的 QQ 号发起查询 → 机器人直接回复「请先绑定」，不做任何数据返回。

### 3.4 数据隔离

- **班级级隔离**：知识库、题库、学生名单、答题数据按班级独立存储；A 班学生检索不到 B 班知识库，即使课程名相同。
- **教师可见范围**：教师仅能查看自己所带班级数据，不提供跨班聚合视图。
- **查询受控**：群内可查字段由本班教师逐项开启，未授权字段直接拒绝回答，不做模糊返回。
- **群内隐私**：查询结果只对提问学生本人可见，机器人不回显他人数据。

## 4. 功能需求

### 4.1 课程知识库与智能问答

#### 4.1.1 上传与解析（✅ 已决，R2-3）

| 项 | 规则 |
|---|---|
| 支持格式 | PDF、Word（doc/docx）、PPT（ppt/pptx）、Markdown、TXT |
| 文字层检测 | PDF 抽取文本量低于阈值即判定为扫描件，**明确拒绝并提示**「该文件为扫描件，暂不支持，请上传文字版」 |
| PPT 解析 | 仅解析文本框文字，图片与图形内文字不做 OCR |
| 批内容错 | 单文件解析失败不阻塞整批，其余文件正常入库，失败清单回显原因 |
| 切片 | 【修改】按段落 + 标题层级切分；每个 chunk 元数据含：文档名、章节标题、页码、文件 ID。文档名以冗余列 `doc_name`（VARCHAR 200）随切片落库；文档改名时，在同一事务内按 `doc_id` 同步 `UPDATE` 全部切片的 `doc_name`，不引入消息队列或后台任务 |
| 标签 / 版本管理 | 🔜 二期 |

#### 4.1.2 引用规则

- 学生提问只能命中本班对应课程知识库，禁止跨库检索。
- 每次回答必须附出处：文档名 + 章节 + 页码，原文片段与讲解分区呈现，可点击跳转原文定位。
- 无可靠命中的提问，回答「知识库中未找到相关内容」并记录该问题，作为资料补充依据，禁止用通识记忆编造。

#### 4.1.3 检索策略（一期）

| 策略 | 一期状态 | 规则 |
|---|---|---|
| 查询标准化 | ✅ 开 | LLM 把口语化提问改写为书面表述，修正错别字与术语；**原始问题必须保留为独立一路检索** |
| 多 Query 扩写 | ✅ 开，**上限 3 路** | 扩写后逐条检索去重合并；改写结果做语义一致性校验，偏离原始意图直接丢弃 |
| 双路召回 | ✅ 开 | BM25 关键词 + 向量检索（Qdrant） |
| 重排序 | ✅ 开 | 对合并候选做 rerank，取 Top-K |
| HyDE | 🔜 二期 | 二期引入，需置信度阈值开关 |

#### 4.1.4 试题求解场景

学生输入的是题目时，优先召回对应知识点并讲**思路与依据**，而不是直接吐答案；参考答案以折叠形式给出，避免知识库变成作业代写工具。

### 4.2 题库与考试

#### 4.2.1 字段标准（✅ 已决，R1-5）

| 字段 | 必填 | 缺省 |
|---|---|---|
| 题型（单选 / 多选 / 判断 / 填空 / 简答 / 论述） | 是 | — |
| 题干 | 是 | — |
| 选项（客观题） | 是 | — |
| 标准答案 | 是 | — |
| 分值 | 是 | — |
| 解析 | 否 | 空 |
| **知识点** | **否** | **未分类** |
| **难度（易 / 中 / 难）** | **否** | **中** |

- 导入支持 JSON / XLS / XLSX；解析后进入预览态，教师可逐题修改、删除、补齐字段，确认后落库。
- 必填缺失 → 红色拦截；选填缺失 → 黄色提示，可一键使用缺省值。
- 支持草稿留存与预发布；发布模板（时长、分值占比、乱序、提交规则）可复用。

#### 4.2.2 判题严格度（✅ 已决，R3-2）

| 档位 | 判定规则 | 使用场景 |
|---|---|---|
| 严格 | 去首尾空格后完全一致 | 正式考试（教师按卷可选） |
| **智能宽松（默认）** | 归一化（空格、全半角、大小写、的/地/得容错）+ 同义词表 + 多可接受答案 | 日常作业、练习 |
| AI 语义等价 | jev 的 noul 原语判定「两答案是否语义等价」，概率 ≥ 0.85 视为正确 | 教师按卷开启；按空计费 |

- 配置粒度：系统级默认「智能宽松」，试卷级可覆盖，单题可覆盖。
- 同义词表由教师按课程维护，允许为空。

#### 4.2.3 组卷（✅ 已决，R1-5）

| 方式 | 规则 |
|---|---|
| 固定组卷 | 整套题目一致，适合正式考试 |
| 随机组卷 | 有标签时按知识点 / 难度定向抽题；**无标签题目自动回落为整库随机抽题**，不阻塞发布 |
| 乱序 | 题目乱序、选项乱序可分别开启 |

#### 4.2.4 判分与考试规则（✅ 已决，R2-4）

| 题型 | 判分方式 |
|---|---|
| 单选 / 判断 / 多选 | 系统比对标准答案自动判分，提交即出分 |
| 填空 | 按 4.2.2 三档严格度自动判分 |
| 简答 / 论述 | **默认人工批阅**；教师可开启「AI 预评」，AI 结果标注仅供参考，教师确认后方计入成绩 |

- 教师可随时修改标准答案，修改后已提交答卷按新答案重算。
- 试卷含待人工批阅题目时，提交后不立即出总分，学生端显示「待教师批阅完成后公布成绩」与已完成客观题得分。
- **防作弊边界**：不做切屏检测、禁止复制、锁浏览器；只做超时自动提交、题目/选项乱序、答题草稿自动保存（每 30 秒或失焦时保存）。

### 4.3 判分引擎协议（jev 内核）（✅ 已决，R3-1 / R2-1 / R3-3）

#### 4.3.1 jev 能力核实

| 项 | 事实 |
|---|---|
| 来源 | TypeSafe AI，2026-09-15 发布 System One 系列首个模型 Jev |
| 可用版本 | OpenRouter `typesafe/jev-1.14`（最新） |
| 能力边界 | **不生成文本**；返回类型化答案（noul / choice / score），自带概率分布与置信度；jev-1.14 起支持图片输入 |
| 性能 | 延迟 70–500ms；$0.042 / M tokens；结构化输出错误率 0% |

#### 4.3.2 题型 → 决策原语映射

| 题型 | 原语 | 输入 | 输出与用法 |
|---|---|---|---|
| 单选 | choice | 题干 + 选项集合 | 概率分布 + 置信度 → 取最大概率选项比对标准答案 |
| 多选 | 逐项 noul | 每个选项「是否应选」 | 每项概率 → 与标准答案集合逐项比对 |
| 判断 | noul | 题干 + 判断题干 | 概率 ≥ 阈值判为正确 |
| 填空（AI 档） | noul | 学生答案 + 标准答案（含多答案） | 等价概率 ≥ 0.85 判为正确 |
| 简答 / 论述 | score | 标准答案 + 得分点清单 + 档位（0/2/4/6/8/10） | 概率加权期望分 + 置信度 |
| 得分点覆盖 | 逐项 noul | 每个得分点「是否命中」 | 命中矩阵 → 用于生成扣分点与讲评依据 |

- 所有调用支持批量：同一次请求内多题合并，降低延迟与成本。
- 判分结果统一落库为结构化 JSON（得分 / 依据 / 扣分点 / 知识点 / 置信度 / 原语原始输出），保证可回放。

#### 4.3.3 置信度合成与复核

| 因子 | 权重 | 说明 |
|---|---|---|
| jev 原生置信度 | 0.60 | 模型返回的 scalar confidence |
| 得分点覆盖率 | 0.25 | 命中得分点数 / 总得分点数 |
| 异常检测 | 0.15 | 答案 < 5 字、复制题干、格式异常等 |

- 合成置信度 < 0.6 → 自动进入人工复核队列，不允许直接计入成绩。
- 阈值一期固定写配置，不做可调 UI。

#### 4.3.4 讲评文本生成

- jev 不生成文本，因此讲评由 DeepSeek **按需生成**：学生点击「看讲评」或教师批量生成时触发，避免平时烧钱。
- 入参：题干、标准答案、得分点、jev 判分结果与扣分点；出参：针对性讲评 + 知识点复习建议。
- 生成失败兜底：直接展示得分点命中的结构化结果，不停用功能。

### 4.4 错题本（轻量版）（✅ 已决，R3-4）

- **收录**：答错即自动入库，记录来源（考试 / 练习）、时间、知识点（无则「未分类 / 综合复习」）。
- **筛选**：按题型、时间范围过滤。
- **重做**：单题重练，提交后显示解析与讲评。
- **只练错题**：一键进入错题集中练习模式。
- 明确不做：知识点筛选、复习材料推送、错题导出/分享。

## 6. 技术架构（✅ 已决，R2-2）

| 模块 | 选型 | 理由 |
|---|---|---|
| 后端 | FastAPI（Python） | 异步、与 LLM 调用生态契合 |
| 前端 | Vue3 + TypeScript | 现有技术栈，AI 编程提速明显 |
| 关系库 | MySQL | 业务数据与班级隔离 |
| 向量库 | Qdrant（单机 Docker） | 轻量、一条命令起，规模够用 |
| 缓存/限流 | Redis | 会话、问答缓存、XP 日封顶计数 |
| 文件存储 | 本地磁盘 | 一期不上 MinIO/OSS，减少组件 |
| 部署 | Docker Compose 一键起 | 云服务器 + 域名 HTTPS，满足机器人回调 |

**策略接口（预留迭代空间）：**

1. 检索策略层：`retrieval_strategy` 接口，实现类 = BM25 / 向量 / 双路融合；二期 HyDE 作为可插拔前置策略。
2. 判分器层：`grader` 接口，实现类 = 客观规则判分 / 填空严格度判分 / jev 判分 / DeepSeek 讲评；回退实现 = DeepSeek 直接判分（jev 不可用时整体切换，协议不变）。
3. 机器人能力层：`bot_capability` 接口，实现类 = 官方 API / mock，配置切换。

所有可选能力（AI 预评、某档判题严格度、某类推送）走配置开关，默认关闭或按卷开启。

## 7. 风险与防控

| 风险 | 影响 | 防控 |
|---|---|---|
| jev 单 provider 不可用 | 判分链路断裂 | 判分器接口层内置 DeepSeek 回退实现，协议与数据结构不变，切换只改配置 |
| QQ 机器人审核未批 | 演示链路断链 | 沙箱群优先；MCP 能力层可 mock；录制视频兜底 |
| 扫描件解析为空 | 学生拿不到答案 | 上传即检测并明确拒绝，不静默入库 |
| 模型幻觉 | 问答无依据、判分误判 | 强制引用原文；无命中即拒答；jev 概率 + 置信度阈值 + 人工复核 |
| 成绩争议 | 学生不认可 AI 分数 | 标注仅供参考；保留结构化判分依据；教师改分留痕 |
| 经验值被刷 | 成长体系失真 | 5 秒阈值、日封顶 200、登录去重、错→对才计 |
| 版权与内容 | 侵权风险 | 平台不内置公共题库；上传页版权提示 |
